# OWASP Security Report Artifacts

This document describes the output artifacts generated by the OWASP Security Workflow, including the newly added HTML and YAML format reports.

## Overview

The central OWASP Security Workflow generates comprehensive security scan reports in multiple formats to support different use cases:

- **JSON**: Machine-readable format for integration with other tools
- **YAML**: Human-friendly structured format for configuration and documentation
- **HTML**: Interactive web-based reports for stakeholders and compliance documentation
- **Markdown**: Quick summary format for GitHub integration

## SAST Artifacts (Semgrep)

### semgrep.json
**Format**: JSON  
**Purpose**: Machine-readable results from Semgrep code scanning  
**Content**:
- Raw findings with metadata (check ID, severity, file path, line numbers)
- CWE and OWASP mapping information
- Parsing errors if any

**Example Structure**:
```json
{
  "results": [
    {
      "check_id": "rules.python.lang.security.injection.sql.sqlalchemy-string-formatting",
      "path": "app.py",
      "start": { "line": 42, "col": 5 },
      "extra": {
        "severity": "HIGH",
        "message": "String formatting allows SQL injection",
        "metadata": {
          "cwe": "CWE-89",
          "owasp": ["A03:2021 - Injection"]
        }
      }
    }
  ],
  "errors": []
}
```

### semgrep.yaml
**Format**: YAML  
**Purpose**: Human-readable structured results for documentation and configuration management  
**Content**: Same data as semgrep.json in YAML format

**Use Cases**:
- Configuration management systems
- Documentation and audit trails
- Version control friendly format
- Readable in text editors without JSON parsing

### semgrep.html
**Format**: HTML (Interactive)  
**Purpose**: Executive-friendly security report with visual organization  
**Features**:
- Color-coded severity levels (Critical, High, Medium, Low, Info)
- Summary dashboard with finding counts by severity
- Collapsible detailed findings with:
  - Rule ID and description
  - File path and line number
  - Severity badge
  - CWE and OWASP mapping
  - Full metadata in structured format
- Print-friendly stylesheet
- Responsive design for mobile viewing
- JavaScript toggle for expanding/collapsing findings

**Use Cases**:
- Security team reviews
- Executive dashboards
- Compliance documentation
- Print to PDF for reports
- Email distribution

### sast-normalized.json
**Format**: JSON  
**Purpose**: Normalized findings with OWASP categorization  
**Content**:
```json
[
  {
    "tool": "Semgrep CE",
    "rule": "rules.python.lang.security.injection.sql.sqlalchemy-string-formatting",
    "severity": "HIGH",
    "path": "app.py",
    "message": "String formatting allows SQL injection",
    "cwe": "CWE-89",
    "owasp": "A03:2021 - Injection"
  }
]
```

### sast-summary.md
**Format**: Markdown  
**Purpose**: Quick summary for GitHub workflow runs  
**Content**:
```markdown
# SAST summary

Findings: 15
```

## DAST Artifacts (OWASP ZAP)

### zap.json
**Format**: JSON  
**Purpose**: Machine-readable OWASP ZAP scan results  
**Content**:
- Identified security alerts/vulnerabilities
- Risk levels (Critical, High, Medium, Low, Info)
- Alert descriptions and solutions
- Affected URLs and parameters
- Multiple instances per alert

**Example Structure**:
```json
{
  "site": [
    {
      "name": "https://example.com",
      "alerts": [
        {
          "name": "SQL Injection",
          "riskcode": "3",
          "desc": "SQL Injection attack detected",
          "solution": "Use parameterized queries",
          "reference": "https://owasp.org/www-community/attacks/SQL_Injection",
          "instances": [
            {
              "method": "GET",
              "uri": "https://example.com/search?q=test",
              "param": "q"
            }
          ]
        }
      ]
    }
  ]
}
```

### zap.yaml
**Format**: YAML  
**Purpose**: Human-readable ZAP results for documentation  
**Content**: Same data as zap.json in YAML format

**Use Cases**:
- Infrastructure-as-code documentation
- GitOps workflows
- Configuration management
- Readable baseline comparisons

### zap.html
**Format**: HTML (Interactive)  
**Purpose**: Professional security assessment report  
**Features**:
- Gradient header with OWASP branding
- Summary dashboard with alert counts by risk level
- Organized by target URL/site
- Collapsible alert details with:
  - Alert name and risk level badge
  - Description and recommended solution
  - OWASP and CWE reference links
  - List of affected instances (URLs, parameters, HTTP methods)
  - Visual hierarchy and severity coloring
- Compact view for high-volume instances (shows first 10, indicates remaining count)
- Print-friendly styling
- Interactive JavaScript for expanding details

**Use Cases**:
- Security assessment reports
- Stakeholder communication
- Penetration testing documentation
- Risk assessment presentations
- Audit trail and compliance evidence

### zap.md
**Format**: Markdown  
**Purpose**: GitHub workflow summary  
**Content**: Generated by ZAP container directly

## Artifact Access in GitHub Actions

All artifacts are automatically uploaded to the GitHub Actions workflow run:

1. **In the workflow run page**: Click the artifact name (e.g., `sast-abc123def456`) to download
2. **Programmatically**: Use GitHub API to retrieve artifacts
3. **In pull requests**: Linked in workflow results or as comments

### SAST Artifact (example: `sast-1a2b3c4d5e6f`)
```
sast-1a2b3c4d5e6f/
├── semgrep.json              # Machine-readable findings
├── semgrep.yaml              # Human-readable findings
├── semgrep.html              # Interactive report
├── sast-normalized.json      # OWASP-categorized findings
└── sast-summary.md           # Quick summary
```

### DAST Artifact (example: `dast-1a2b3c4d5e6f`)
```
dast-1a2b3c4d5e6f/
├── zap.json                  # Machine-readable alerts
├── zap.yaml                  # Human-readable alerts
├── zap.html                  # Interactive report
├── zap.md                    # Markdown summary
├── dast-normalized.json      # OWASP-categorized alerts
└── dast-summary.md           # Quick summary
```

## Format Comparison

| Format | Machine-Readable | Human-Readable | Actionable | Best For |
|--------|-----------------|-----------------|-----------|----------|
| JSON   | ✅ Yes           | ❌ No            | ✅ Yes     | Tool integration, automation |
| YAML   | ✅ Yes           | ✅ Yes           | ✅ Yes     | Docs, configs, audits |
| HTML   | ❌ No            | ✅ Yes           | ✅ Yes     | Reports, stakeholders, print |
| Markdown | ⚠️ Partial      | ✅ Yes           | ⚠️ Partial | Summaries, GitHub comments |

## Processing Pipeline

```
SAST Pipeline:
  Docker Semgrep → semgrep.json
                 ├→ convert_json_to_yaml.py → semgrep.yaml
                 ├→ generate-html-report.py → semgrep.html
                 └→ map-findings.py → sast-normalized.json
                                   → sast-summary.md

DAST Pipeline:
  Docker ZAP → zap.json, zap.md
             ├→ convert_json_to_yaml.py → zap.yaml
             ├→ generate-html-report.py → zap.html
             └→ map-zap.py → dast-normalized.json
                            → dast-summary.md
```

## Security Gate Integration

The `security-gate.py` script uses the normalized JSON artifacts to enforce policy:
- Reads findings from normalized JSON files
- Applies configured thresholds (e.g., FAIL_ON_SAST=ERROR)
- Reports pass/fail status
- Can be integrated with GitHub branch protection rules

## Recommended Workflows

### For Security Teams
1. Download `semgrep.html` and `zap.html` for detailed review
2. Use normalized JSON for metric tracking
3. Reference OWASP mappings in reports

### For Development Teams
1. Review findings in HTML format
2. Reference specific file paths and line numbers
3. Track remediation in issue tracking system

### For Compliance & Audit
1. Archive HTML reports for audit trail
2. Use YAML format for change tracking in Git
3. Extract CWE/OWASP mappings for regulatory compliance

### For Automation/SIEM
1. Parse normalized JSON for metric ingestion
2. Integrate risk scoring with existing systems
3. Trigger remediation workflows based on severity

## Customization

To customize report generation:

1. **HTML Styling**: Edit `scripts/generate-html-report.py` CSS section
2. **YAML Format**: Modify `scripts/convert_json_to_yaml.py` for different structures
3. **Normalization**: Update `scripts/map-findings.py` and `scripts/map-zap.py` for OWASP mappings

## Troubleshooting

### Missing HTML Reports
- Ensure `generate-html-report.py` is executable
- Verify Python 3 is installed and in PATH
- Check error logs in GitHub Actions output

### Large HTML Files
- HTML can be large with many findings (1000+ findings)
- Use browser "Save As" to persist report locally
- Consider splitting reports by severity

### Character Encoding Issues
- All scripts use UTF-8 encoding
- Ensure terminal/editor supports UTF-8
- Check file encoding if display issues occur
